# 桌面窗口尺寸与设置合并

Relatum 主窗口禁止通过四边、四角拖动调整大小，窗口尺寸通过全局设置“系统”调整。最小尺寸为 720×480 逻辑像素，上限按当前显示器工作区计算，保留取消 1920×1200 固定上限和 32px 扣减的改动。标题栏移动、最大化、最小化、系统窗口过渡及 DWM 圆角继续保留。

## 原生实现与数据

`desktop.py` 的边缘命中及非客户区处理恢复为 `06f70c7` 之前的方式：`WM_NCCALCSIZE` 声明整窗为客户区，不预留系统缩放边框；`WM_NCHITTEST` 将四边及四角的缩放命中转为客户区。此次拖边功能新增的偏蓝边带随预留边框一并移除，不增加网页覆盖层、全局鼠标钩子或逐帧自绘缩放。

删除拖边专用的 Sizable 设置、缩放热区、tracking 约束、非客户区绘制拦截和为缩放边框增加的还原尺寸补偿。原生 ShowWindow 恢复旧版直接调用方式。保留尺寸设置使用当前窗口 DPI 的处理。

实际尺寸以 `GetWindowPlacement` 为准，桥接中的尺寸字段只是镜像。设置成功和关闭保存真实还原矩形；DPI/工作区变化继续通过可取消的单次后台任务合并同步。拖边完成处理已删除。原生消息处理不执行 JavaScript 或文件写入，不增加轮询或连续 RAF。退出取消待处理任务，GUI 循环结束后释放原生回调引用。

状态继续使用 v2：完整模式为 `data/window-state.json`，精简模式为 `data/desktop-sessions/<组合>/window-state.json`。尺寸按逻辑像素保存，最大化/最小化不替代普通尺寸，不迁移已有记录。独立 Markdown 文件窗口使用自己的原有原生窗口和状态逻辑。

## 设置与接口

旧客户端设置弹窗及左下角入口已经移除。全局设置“系统”统一提供三个尺寸预设、宽高输入和单一启动器免弹窗开关，两种首页外壳共用控制器。普通浏览器不创建这两个桌面专属控件。窗口尺寸及启动器偏好不参与系统分类恢复和全部恢复。

保留 `CanvasDesktop.getRestoredSize/setRestoredSize` 及 `{width,height,limits}` 返回值。内部 `canvasdesktop:window-size` 事件沿用同样的 detail，在设置成功或显示器约束变化时发布。读取仅在进入系统分类时进行；离开或关闭后拒绝迟到结果。尺寸通知保留未提交输入，应用期间禁用重复提交，失败保留输入并显示错误。最大化时应用尺寸先还原。启动器沿用原生桥接、原子写入 `data/launcher-settings.json`、提交串行及失败回滚，不依赖旧弹窗 DOM。中英文说明已移除“拖动边缘调整大小”的提示。
