# 使用统计 v2 数据说明

统计从首次启用 v2 时开始。`data/canvas-activity.json`、`data/start-page-activity.json` 和 `data/career-report.json` 全应用停用，既不读取、写入，也不迁移或回填；旧文件保留。现有内容只参与当前库存。

`data/usage-v2.sqlite3` 使用标准库 SQLite 与 WAL。时段按当地午夜拆分，连续片段合并，总时间取真实并集；内嵌画布属于笔记细分，各分类时间不能相加当总时间。收据使失败重试幂等，设置表记录分类开关生效时间，关闭保留历史。已启用功能默认记录，专注钟、日记和生涯排除。日期、分类和项目都有索引；编辑器直接查询单个项目，生成读取使用 WAL 快照，不长期占用业务保存锁。

项目 ID 与文件名分离，应用内改名、移动和回收站操作映射同一身份，删除保留已记录时间。私有身份表保存授权定位符；报告仅保存身份、名称、数值与关系，没有正文或绝对路径，也不向文档写统计。

前台阅读和思考计入，失焦、隐藏、最小化暂停；异常间隔不补记休眠。桌面壳发送原生最小化/还原通知，避免 WebView2 保留焦点时继续计时，同时释放生涯绘制资源。每 30 秒提交，切换/关闭提交尾段，同源 iframe 共用顶层所有者。失败队列以 `canvas:usageQueue:v2:<owner>` 留在本机，服务恢复可用或后续窗口重试；请求按 UTF-8 字节分批，保留原收据。后续启动裁剪了功能时，已捕获的有效尾段仍可提交。未持久化的最后片段在异常退出时仍可能丢失，最多一个正常提交周期。

`data/career-report-v2.json` 是手动生成的冻结报告。普通读取、日期筛选和章节切换只使用快照；全部、近 30 天、近 90 天、自然年和自定义日期均使用冻结数据，自然年可选择年份。库存标注生成时规模。生成先冲刷队列，再用独立线程读取来源，成功原子替换、整体失败保留上一份 v2。每个来源独立标明完整性；损坏研究主文件只报未读取，不恢复备份、不隔离、不重写；画布库登记也采用纯只读入口。无法读取的来源显示未知及未读取数量，不能当作零。

接口：GET `/api/usage/state`、POST `/api/usage/batch`、GET `/api/career/report`、POST `/api/career/generate`、GET `/api/career/jobs/{id}`。重复生成请求复用运行中的任务。旧提交和旧生成接口返回 410，旧报告读取接口移除。

先退出所有 Relatum 窗口，再备份数据库和仍存在的同名 `-wal` / `-shm` 文件以及报告。删除统计库清空新历史与分类配置，内容不受影响；删除报告仅清空冻结报告，下次手动生成仍可使用新账本。

## 已删除笔记的统计归档与备份

全局设置 → 使用统计 → 数据管理提供“导出统计备份”和“归档已删除笔记的统计”。`assets/usage-management.js` 首次进入分类才加载；概览只在打开、归档完成和手动刷新时读取，不轮询或读取笔记正文。笔记未启用时只提供备份。恢复默认只恢复采集开关，不归档或删除历史。

归档分为预览、选择、确认。明确已删除项默认勾选；旧路径缺失可能是软件外改名、移动或删除，单独列为待核对候选，默认不选。仍存在或已恢复的旧路径、不可读目录、权限异常、链接/重解析点及无法安全核验的路径排除。每组每页 40 项，跨页保留选择；预览有效期 10 分钟。执行前冲刷当前窗口队列，服务端持笔记锁重新核验所选身份及路径；变化时整个操作取消。响应丢失可保留原选择重试，同一已提交请求不重复累计。

`usage_management.py` 协调核验、预览、事务及备份。SQLite 新增 `archive_items`（匿名旧身份/归档时点）、`archive_routes`（加盐路径摘要/截止时点/匿名身份，处理旧队列）、`archive_years`（匿名身份/年份，保留年度活跃项目数）、`archive_requests`（请求摘要及无名称结果）。`meta.archiveRevision/archiveSalt/archiveReportPending` 分别管理归档版本、路径摘要盐和报告待生成状态。原实体名称、明文路径别名、指纹及逐篇时段/操作记录在同一事务删除；不保存正文。

时段并入匿名 `archive:notes`，合并重叠与连续区间；操作按日期、种类合并。总时长、每日/分类/工作区时间、小时分布、活跃日期、操作次数及年度活跃项目数量不变。旧队列按路径摘要与时间边界归入匿名记录；同路径重建、恢复或重新发现的真实笔记使用新身份。成功新建接管原别名时也只留下加盐时间路由，避免新建后、归档前收到的旧队列误记到新笔记；旧身份在归档前仍保留原明细，归档后才并入匿名组。生涯排名排除匿名组，下面另列累计归档篇数和筛选范围内时长。旧笔记间重叠时间只计一次，预览逐篇时长之和不等同于汇总使用时间。

存在报告时，归档后立即使旧快照失效、清理并自动重新生成；从未生成则不主动创建。读取校验归档版本，进程中断或清理失败也不展示旧明细。生成发布通过 SQLite 写事务核验版本；归档交错时最多重新构建三次，不能写回旧名称。失败保留归档结果，生涯提示报告待重新生成，可重试。进入/还原检查版本，同源窗口另用 `canvas:usageArchiveRevision:v1` 的纯版本通知撤下内存报告。快照增加 `history.archiveRevision/archivedNotes`；旧 v2 缺省视为未归档，不迁移更早旧账本。

接口：GET `/api/usage/management` 返回明细及归档数量；POST `/api/usage/archive-preview` 返回 token 与 id/name/kind/seconds/firstDay/lastDay 候选；POST `/api/usage/archive-notes` 接受 `{token,ids}`，返回 count/archiveRevision/repeated 和可选报告 job。笔记未启用时归档返回 403，候选变化/过期返回 409。GET `/api/usage/backup` 下载 ZIP；桌面 POST 同路径打开原生“另存为”，取消不写入，确认后原子复制到选择的位置；选择器等待不持业务锁。

备份采用 SQLite 在线备份 API，包含已提交 WAL 页，不直接复制运行中的库。ZIP 内有 `usage-v2.sqlite3`、可读取且版本有效的 `career-report-v2.json`（若有）及恢复说明，不含 Markdown 正文或附件；整个统计库的采集开关、旧名称和私有定位信息仍属于备份。用户未主动导出时不留自动副本，临时导出文件随请求清理。

恢复前退出所有 Relatum 窗口，先另行备份当前统计库、同名 WAL/SHM 和生涯报告。确认应用全部退出后移除当前 `usage-v2.sqlite3-wal` / `usage-v2.sqlite3-shm`，用 ZIP 中的库和报告替换 `data/` 下同名文件。ZIP 没有报告时移除当前旧报告，再启动后手动生成。恢复替换所有分类的历史和采集开关，不合并两套账本、不恢复正文；首版无导入界面。归档无法直接撤销逐篇明细，数据库文件不保证立即缩小。

验证：`python -B -m unittest tests.test_usage_management`、`node tests/usage-management-browser.js`。浏览器设置 `RELATUM_PYTHON / RELATUM_PLAYWRIGHT / RELATUM_EDGE_PATH`。夹具仅接受全新空临时根，覆盖跨年/午夜、重叠、项目数、迟到/重复请求、外部变化/恢复/权限异常、备份完整性、并发生成及失败重试、中英文/深浅/窄窗、分页、键盘确认和迟到预览；校验合成正文与附件哈希不变。

手动验收可用 `tests/career-demo-fixture.py`，必须指定全新的空 `RELATUM_DATA_ROOT`；脚本拒绝仓库数据根和非空目录。生成 200 篇笔记、32 张主画布、5 个内嵌文件、16 个研究页面、6 个子电路及一年波动记录，包含密集/稀疏关系、连续缺口、跨午夜和关闭采集区间。数据库显式写入 `meta.demo=1`，报告顶部显示“验收数据”，重新生成继续保留标记。正常数据库不设置此标记。生成前后校验内容哈希，验收文件不提交 Git。
