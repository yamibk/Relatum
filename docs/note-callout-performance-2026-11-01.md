# 笔记长文 Callout 展示计算 · 2026-11-01

## 定位

前三轮长文优化已经处理可见区域富块扫描、异步高度及行内候选。在已经浏览过很多章节的文档中，Callout 的祖先及折叠模型仍需要完整块集合；原模型每次重新生成标题、图标、配色及颜色分量，折叠判断也再次生成同一描述。正文编辑造成位置映射后，原有按块集合身份缓存的树也需要重新建立。这些展示信息实际只依赖类型、标题和折叠后缀。

用静态资产、一次性 Edge 和 4MiB 合成文档做 CPU 采样，确认大量提示块的输入热路径仍有重复 `noteBlock()` 配色计算。含目录的长文另有语法索引映射开销，本次没有更改该索引；普通表格文档作为不含提示块的对照。

## 改动与边界

`assets/note-live-editor.js` 的 `completeSpec()` 为 Callout 生成展示信息，包含原 `noteBlock()` 的描述和解析后的颜色分量。位置映射自然共享同一信息；局部重扫时，仅在原类型、标题和折叠后缀完全相同的情况下复用。正文改动不重新计算配色，任何标题字段改动都会重新计算。

祖先树、折叠判断、标题投影、嵌套控件及源码折叠使用同一描述。折叠状态仍从当前控制器读取，焦点和选区仍实时参与颜色块的隐藏标题判断；普通提示块跳过无关标题行读取，同次布局只查询一次输入焦点。完整祖先树、嵌套底色及折叠范围继续使用原模型。

展示信息随既有块对象存续，不保留编辑器、DOM、路径或额外正文，没有独立条目列表或跨笔记缓存。没有增加设置、后端接口、磁盘写入、观察器、计时器或持续绘制；Markdown、保存、撤销、阅读模式渲染及资源加载协议不变。本次不调整字体、宽度、主题或用户已有偏好，也不重新打包。

## 验证与复现

沿用宿主 `RELATUM_PLAYWRIGHT / RELATUM_EDGE_PATH / RELATUM_PYTHON`，不安装项目依赖：

```powershell
node tests/note-callout-performance-browser.js
node tests/note-callout-performance-browser.js --quick
node tests/note-live-editor-regression.js
node tests/note-callout-selection-regression.js
node tests/note-callout-browser.js
node tests/note-nested-callout-browser.js
node tests/note-callout-resources-browser.js
node tests/note-live-presentation-browser.js
node tests/note-input-browser.js
node tests/note-scroll-preparation-browser.js
node tests/note-viewport-browser.js
```

专项默认基线为 `30ff695`，可用 `RELATUM_NOTE_CALLOUT_BASELINE` 指定其他包含原 Callout 模型的提交。基线源码只读加载，不切换工作区文件；只托管静态资产，合成长文、浏览器配置及报告均在临时目录。性能测量与其他浏览器回归顺序执行。

专项直接加载原祖先树、原折叠判断和原行内排版，与当前生产状态对照 1309 组装饰的范围、样式、控件类型及数据，覆盖普通/颜色/白色/未知类型、嵌套、折叠、标题编辑、多可见区间、多选区、聚焦及候选状态。源码回归逐项验证标题字段失效、位置和正文编辑复用、颜色精确一致及折叠状态即时变化。

性能基准以 400KiB、1MiB、4MiB 的提示块混排和 4MiB 表格对照，分别在初访及浏览 30 个位置后测量光标移动、普通输入与细粒度原生滚动事件；三轮基线/当前交替。配色生成次数另在独立的 20 次光标移动中统计，不将计数探针混入耗时采样。报告保留原始数据，正文必须一致且继续虚拟挂载。`--quick` 只跑一轮 400KiB，已接入 `tests/run-note-checks.ps1 -Browser`。

同步 JS 排版及输入事务耗时不等同系统输入延迟或物理帧率，浏览器候选事件不替代 WebView2 与真实微软拼音候选窗人工验收。短文及没有 Callout 的文档不承诺同等收益。

## 三轮对照结果

同机 Edge、1280×900，基线 `30ff695`，基线/当前交替三轮。下表为浏览 30 个位置后，每轮 P95 的中位数；输入事务包含同步编辑器更新，行内排版是其中及随后视图更新的单项采样，不能将两者相加。

| 合成文档 | 行内排版 P95，基线→当前 | 同步输入事务 P95，基线→当前 |
| --- | ---: | ---: |
| 400KiB 提示块混排 | 4.2→1.0ms | 9.8→3.9ms |
| 1MiB 提示块混排 | 10.6→1.8ms | 20.4→6.9ms |
| 4MiB 提示块混排 | 11.7→2.3ms | 30.6→13.8ms |
| 4MiB 表格对照 | 0.4→0.4ms | 13.0→12.7ms |

提示块混排的同步输入事务 P95 约减少 55%–66%。独立的 20 次光标移动中，提示块描述生成次数分别由 19640、49580、51880 次降至 0；这个计数仅表示固定展示信息的生成，没有跳过实时折叠或选区计算。最终正文 DOM 两版一致，提示块场景分别为 188、192、192 个，表格为 236 个。所有采样阶段正文保真，1309 组新旧装饰对照通过，浏览器无脚本错误。

4MiB 提示块混排的往返后光标移动事务 P95 中位数为 6.6→2.8ms，滚动期间的单项行内排版 P95 为 11.8→2.3ms；滚动每轮仅采到 7–9 次排版，不据此宣称总体滚动帧率提升。初访同步输入事务 P95 为 9.6→9.2ms，没有明显变化；收益主要出现在浏览过较多提示块后。

原始各轮输入、光标移动、滚动、初访及往返数据见系统临时目录 `relatum-note-callout-performance-wTlULt/report.json`。普通表格的差异只视为没有明显退化，不据此宣称提速；也不把提示块密集长文的降幅推广到全部 Markdown。

改后顺序通过 15 项既有回归：编辑器源码、Callout 选区、工作区契约、Typora 语法、扩展语法索引、可见候选、提示块显示、嵌套提示块、提示块资源释放、实时排版、输入、长文滚动准备、工作区视口恢复、4000 格表格交互、图片文字。长文滚动八类场景通过，4MiB 混排重访的源码表格可见帧和锚点变化均为 0；资源回归没有遗留 MathJax 记录。语法及差异检查通过。全部日志位于系统临时目录 `relatum-callout-validation-6ff6192f57ac4130945d2d039b4a1ac1`，只使用隔离数据。
