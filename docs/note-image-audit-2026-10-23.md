# 笔记图片与运行稳定性调查 · 2026-10-23

重点排查图片插入、剪贴板、拖放、异步选区交接、自动保存和图片测量，同时回归笔记输入、滚动、索引、搜索及图谱的既有边界。所有测试使用一次性笔记库和浏览器配置；桌面程序也使用隔离数据根，现有用户正文、图片、`data/`、画布和发布资源保持原样。

## 已复现的问题

基线为 `9f9a80d`。同一真实本地 API 下由测试替换旧/新前端响应；延迟只加在测试网络响应上，不修改生产计时。

| 场景 | 基线行为 | 修复后的行为 |
| --- | --- | --- |
| 上传未完成时选中另一段正文 | 图片替换后来选中的文字，原文丢失 | 在初始位置插入，保留后来的选区与文字 |
| 上传时在初始位置之前输入 | 按完成时的光标插入，位置改变 | 临时范围随 CodeMirror 的真实变更映射 |
| 上传期间改写原待替换选区 | 迟到图片继续插入 | 取消插入，不覆盖新内容 |
| 切到其他笔记，再回到原路径 | 旧上传重新写入已重开的正文 | 核对文档身份及打开序号，拒绝旧结果 |
| 最小化后立即还原 | 旧响应仍可插入 | 可见生命周期变更后保持取消 |
| 同批导入 40 张图片 | 40 次正文变更 | 1 次正文变更；成功图片保持原顺序 |
| 超过 40MiB 的文件 | 先执行 FileReader/Base64 和 JSON，再由后端拒绝 | 读取前拒绝，零读取、零上传 |
| FileReader 被取消 | Promise 不结清，导入操作一直等待 | 正常进入失败收尾，下一次导入可继续 |
| 没有响应的图片请求 | 没有专项超时 | 45 秒取消请求并释放队列 |
| 图片状态不变的 100 次普通光标移动 | 100 次图片工具栏更新 | 0 次重复通知 |

超大文件的前端测试通过覆盖 `File.size` 验证读取顺序，不实际分配数百 MiB。取消和超时用测试替身确定性触发；旧的取消 Promise 不结清不等于已证明整页主线程死循环。批次更新次数是明确的工作量对照，不把单轮上传耗时当作可靠帧率或速度结论。

## 连续图片点击导致的整页卡死

用户反馈来自微信复制图片，使用 `RelatumLauncher.exe` 选择笔记＋画布工作区，连续粘贴两三张后再点击就完全卡死。继续调查确认，基线 `232d7e7` 下使用普通 400×200 PNG 也能稳定触发：同一文档连续三次真实 Ctrl+V，然后选中图片并点击图片右侧空白。先前的四次剪贴板测试每次都重置正文；40 张批次测试只检查插入，没有执行图片之间的鼠标操作，因而遗漏了这个路径。

页面外 Node 超时触发后，用 CDP 暂停主线程，调用栈停在原离线 CodeMirror 的 `Wr`（光标跳过原子范围）、`nf`（鼠标选区归一化）和 `RangeSet.between()`。相邻图片的原子范围包含换行，产生 `[0,58]`、`[57,116]`、`[115,174]` 这类交叠；增量范围集的 `between()` 实测遍历顺序为第一、第三、第二条。鼠标落点校正因此在 57 和 116 等端点间来回移动，每一轮又重置方向判断，形成同步死循环。页面自身的定时器和交互一起停住；此复现不依赖超大图片或源应用特有的剪贴板格式。

`assets/note-live-editor.js` 在块投影提供 `EditorView.atomicRanges` 时，使用 `mergeBlockAtomicRanges()` 将真正交叠的范围合并成互不交叠的并集。使用 `iter()` 的源码顺序，按原 RangeSet 对象在 WeakMap 中缓存，重复命中复用结果。原来的逐块 id 和范围仍供增量更新、候选映射、删除和选中使用；正文、真实空行、每张图片的投影及 Markdown 内容保留。修复仅改变提交给光标跳过逻辑的范围，CodeMirror 离线文件保持原样。

`tests/note-live-editor-regression.js` 用实际 StateField 和原子范围 facet 验证逐次粘贴、乱序选中更新、正文/空行分隔、候选映射、删除与缓存；测试中有步骤上限的光标解析副本可让回归明确失败，生产没有这个测试保护。浏览器测试继续用未修改的 vendor 和真实鼠标，页面外 watchdog 可以捕获同步卡死，并在失败时尝试暂停、输出堆栈。调查中的堆栈采样提前启用 Debugger，日常运行只在超时后尝试开启，无法暂停时仍报告页面外超时并结束隔离进程。

## 内存与计算边界

原上传只验证压缩文件字节数，尺寸很大的压缩图片可能以很小的文件触发大量解码内存。新增标准库文件头尺寸检查，覆盖 PNG、JPEG、GIF、BMP 和 WebP 的 VP8、VP8L、VP8X；不调用 Pillow 或其他图片解码器。已识别尺寸的单边限制为 32768，总像素限制为 67108864，适用于上传、导入及已有图片读取。大图拒绝发生在创建新附件或发送给浏览器之前，原文件与 Markdown 保留。

普通 PNG/GIF/BMP 读取检查只增加 32 字节的头读取。JPEG/WebP 需要时最多扫描 1MiB；这是有预算的风险控制，未知、损坏或元数据超过预算的头仍由原图片加载失败路径处理，不是完整格式验证。解码内存大小仍取决于浏览器、格式及同时可见的图片数量，不能承诺固定 RAM 降幅。

前端保留原 Base64 JSON 接口，读取和上传按批次串行，批量成功后只投影一次；没有增加后台循环。图片文字尺寸先集中读取再写入，重复尺寸不改样式，降低 ResizeObserver/编辑器测量之间的重复失效。图片状态相同不重复遍历和改写整组工具栏控件。

临时插入目标不保留全文字符串，只记录范围、路径和文档序号；完成、取消、文档替换或编辑器销毁时释放。不删除已写入的附件，以免损及共享引用。上传期间用户继续输入时，光标和选区依正常变更映射，不把它们强制恢复到旧状态。
