# 笔记长文滚动准备 · 2026-11-01

## 原因与边界

实时预览保留 Markdown 为唯一数据源。CodeMirror/Lezer 增量解析和虚拟显示普通正文，专用块投影负责表格、图片及公式等。图片延迟加载并异步解码；MathJax 在真实公式出现后按需加载、串行排版；Mermaid 使用原本地 Pele、Worker、可见性调度及结果/高度缓存。

快速到达未浏览区域时，源码到显示块的转换和资源完成可能分属不同帧；实际高度替代估计后，文档总高度及原生滑条比例会变化。CodeMirror 也会补偿滚动位置，因此不能仅用 scrollTop 是否变化判断正文跳动。此次合成测试记录源码锚点的屏幕位置、源码表格可见帧、文档高度及滑条比例。

现有系统设置中的正文预读用于文件树中的其他笔记；缓存档位控制正文、图谱、Mermaid 的结果保留预算，不是当前长文的渲染距离。本次不增加设置，不改变这些预算。

## 实现

- 当前屏使用原 12ms 协作解析预算，完成后立即扫描、提交可确定的块。其后利用 requestIdleCallback（能力不足时单次任务回退）以约 4ms 的解析切片准备前后各一屏。继续沿用公式 32KiB 上下文、完整语法容器及原大小限制，不扩大 CodeMirror 挂载区域，不提前创建整篇 DOM。解析器单步不保证是可抢占的硬实时任务。
- 同一屏的滚动、尺寸变化和投影收尾按原显示帧合并；当前屏与相邻准备共同保留最近两个扫描范围，按正文对象和语法树身份失效，避免两种任务交替覆盖扫描记忆。扫描结果完全相同时复用原块集合和索引。候选输入、隐藏、最小化、宿主停用和 pagehide 停止准备；恢复时只准备当前区域。旧文档的空闲任务不得提交新文档。
- 图片、块公式、表格及 Mermaid 由 MeasuredBlockWidget 组合原控件，只提供数值高度估计及占位。布局身份包含路径、源码、容器、内容宽度、字体、字号、字重、行高、字距、主题、窗口高度和字体加载版本。新增的每编辑器会话提示最多 2048 项、估算 256KiB；值仅含数值尺寸，不保留旧正文、HTML 或编辑器实例。销毁清空。Mermaid 的原控制器、编辑预览高度回退和结果缓存继续保留。
- 图片/公式/图表未完成时使用有效的确定高度占位；只用 min-height 仍会让临时 TeX 源码撑高，因此已知高度期间临时裁切未完成内容，资源明确完成后立即释放占位，再读取真实高度。公式以 typesetPromise 完成为准，不把中途生成的 mjx-container 当作排版完成。加载事件及原公式/图表完成通知复用一个 requestMeasure，微任务合并更新 blockLayoutEffect，不改历史。高度变化时复用原控件和表格输入宿主，继续使用 CodeMirror 的原滚动锚定，不锁滑条。
- 重开及模式切换仍优先使用原源码位置校准。恢复期间不将新屏外数值估计加入初始高度图，以免先改变虚拟空隙再校准；用户的滚轮、滑条、键盘等接管后恢复正常提示复用。Mermaid/Quiz/Cards 保留原有高度机制与交互。

没有新增后端接口、磁盘缓存、用户偏好、观察器、常驻轮询或闲置动画循环；不修改 vendor、正文保存、阅读渲染协议或撤销历史。首次直接跳到未知内容仍可能出现准备时间，未准备图片的真实尺寸也不能凭空确定。

## 细粒度滚动的扫描去重

基线 `f071551` 的当前屏扫描与空闲准备共用一条范围记录。两种任务交替后，即使正文、语法树和范围没有改变，也会再次进入富块重扫；已有的“扫描结果不变则复用”只能省去后续投影更新，不能省去扫描、筛选和排序本身。

现在使用最多两项的范围 LRU，命中后直接跳过富块重扫。正文对象或语法树发生变化时清空旧范围，新增语法、编辑、撤销和切文档仍正常扫描；销毁时释放引用。只保留范围标识和当前文档/语法树身份，不保存额外正文或渲染结果，不增加监听、定时器、偏好或接口。

`node tests/note-scroll-scan-browser.js` 使用同一 Edge、1280×900，合成 3,387,780 字符的 6000 节表格混排文档，先浏览 30 个位置，再做 30 次 1px 的原生滚动事件。三轮基线/当前交替，测量时已知富块约 1972–1989 个：扫描次数中位数为 **62→3**，累计扫描时间中位数为 **120.5→6.9ms**，约减少 94%。这是受控细粒度滚动下的扫描计算量，不是整页耗时或物理帧率，也不代表所有滚动场景都有同等降幅。

每轮另检查正文不变、同区域插入新表格、一次撤销和换到另一篇表格文档，全部通过；源码回归直接验证两种范围交替命中、有界淘汰、正文/语法树变化失效及清理。报告为系统临时目录 `relatum-note-scroll-scan-qU4WTa/report.json`。基线由 `RELATUM_NOTE_SCAN_BASELINE` 指定，默认 `f071551`；`--quick` 只跑一轮，已加入笔记浏览器回归入口。

改后通过长文渲染八类场景（含 1MiB/4MiB）、62 组视口恢复、实时排版、输入、表格交互、工作区滚动及源码/工作区契约回归；日志位于系统临时目录 `relatum-scan-regression-5a1b2b36d2354abca770c3d4062be7f7`。仅改视口扫描去重，不修改笔记文件、保存、用户配置或 vendor，不重新打包。

## 行内排版的可见候选复用

原行内排版对每个可见语法节点、正文行、引用及公式反复遍历全部已发现的富块。已浏览区域增多后，即使当前屏相同、富块集合没有变化，排版计算也随集合增长。初步隔离诊断中，约 3.4MiB 合成长文的已知块从 72 个增加至约 1974 个，同处正文的行内排版 P95 从约 0.5ms 增至 2.1ms。

现在每个可见区间先按首尾完整行筛选相交候选，再让原有包含判断、公式查找和 Callout 装饰复用候选。筛选使用包含边界的相交条件，保留跨屏父块、嵌套及源码顺序，具体装饰条件不变。Callout 的祖先、折叠及隐藏标题模型仍使用全部块，但每次行内排版只计算一次，不在多个可见区间重复生成。候选只在本次调用内存在，没有新增长期索引、DOM、监听、任务或偏好。

专项 `node tests/note-inline-candidates-browser.js` 默认以 `e5d3a28` 为基线（可用 `RELATUM_NOTE_INLINE_BASELINE` 指定）。它只读取静态资产、使用合成 Markdown 及一次性浏览器；完整基准对 400KiB、1MiB、4MiB 文档分别在初访和浏览 30 个位置后测量光标移动、普通输入和原生滚动事件，基线/当前交替三轮。`--quick` 仅跑一轮 400KiB，已接入笔记浏览器回归入口。

同一测试另将原行内排版函数作为测试探针加载，使用相同生产状态直接比较新旧装饰的范围、样式、控件种类和数据。1027 组对照包含嵌套/折叠 Callout、公式内部及跨行父块、表格、图片、引用代码、边界接触、多可见区间、聚焦及跨块/多选区。耗时只表示同步 JS 排版及输入事务，不等同原生 IME 延迟或物理帧率；普通短文不承诺明显改善。
