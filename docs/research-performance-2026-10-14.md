# 研究工作区性能复查（2026-10-14）

本轮找到并修正了批量节点布局、投影展示、直角装饰预览、空绘图缓冲和最小化生命周期中的实际开销。继续使用现有 DOM / Canvas2D / 临时 SVG 渲染，研究 V3 数据、计算语义、端口协议、历史和保存格式沿用原规则。

## 改动与原因

- `research-canvas.js` 原来创建一个节点后立即读取尺寸，而且新节点会重复执行一次展示更新。现在整批挂载/更新后再统一测量，并在测量前应用恢复的相机倍率。拓扑更新和换页共用此路径；节点移动只改位置，不重复写标题、徽标、按钮和端口。
- 投影刷新原来调用完整的节点装饰更新，即使计算结果没有变化，也会重写静态属性和文字。现在结构展示与计算结果分开；结果文字、显隐和状态只在实际不同的时候更新。英文错误/空轨迹也先取得实际显示文字再比较。原有连续显示分片和单步/复位同步展示保持不变。
- `ResearchModel.updateDecorations(..., {live:true})` 原来每次重建全模型索引，绘制层随后重建全部装饰边界和空间索引，小地图重新核对整页。现在按对象 ID / 数组位置更新，通知携带实际对象 ID；只移除/插入相关对象的网格单元并更新相关缩略块。取消、恢复、增删和手势提交收尾仍使用完整校准，草稿保存隔离及单条历史语义不变。
- 标注真实尺寸变化也只更新相关装饰边界。`DecorationIndex.update()` 保留对象顺序，并处理普通单元与超长候选之间的切换、清除空单元；不索引每个单位端点。
- 默认模式的空装饰页原来每次绘制都分配并清空两个完整视口的 Canvas2D 缓冲。没有装饰、框选、吸附或线预览时，两份缓冲各缩至 1×1；新增对象/预览时按实际视口及 DPR 恢复。像素尺寸是缓冲请求规模，不能当作测得的进程内存或显存。
- 静态连线原来按整个世界边界登记网格，远距离连线可能分配巨大网格。现在每条最多 256 单元，超限另存候选身份；查询超出实际网格预算（最多 4096）时直接筛选缓存边界。超长线绘制仍按模型顺序，几何命中距离相同时保持稳定顺序；移动、删除及模型替换同步清理。
- 编辑器原来只用 iframe 自身的 `document.hidden` 暂停仿真。WebView2 的原生最小化通知发给父页，iframe 可以继续保持可见/聚焦。现在同时读取自身和同源父页的可见状态及原生标记，共用幂等交接；画布、标注、计算和仿真停止，保存与已经开始的输入交接继续。恢复沿用模型、镜头和运行意图；显式暂停或已离开的工作区不会被唤醒。仿真控制器的 `activate()` 不再覆盖独立的可见状态。

## 同机对照

- Windows 11 家庭版中文版，10.0.26200；i9-13900HX，24 核 / 32 逻辑处理器。
- Edge 155.0.4283.45，Playwright 驱动，1440×900，DPR 1，低动态。
- 旧源码：`d18b0f7`；新源码：本轮工作区改动。每个规模各三次独立浏览器上下文，耗时取中位数；无应用依赖或构建链变化。
- 构造器测量使用 1200 / 3000 个 Constant，无导线，倍率 25%。计时只包含画布构造/挂载，排除模块加载、网络和编译；不是整个工作区的启动时间。
- 装饰测量使用 3000 条合成线，对单个对象连续提交 30 次预览；测量同步模型/索引/小地图路径，不代表完整拖动帧率。

| 指标 | 旧源码 | 优化后 |
| --- | ---: | ---: |
| 3000 节点构造/挂载中位耗时 | 3593.7 ms | 163.2 ms |
| 3000 节点布局耗时中位数 | 3155.6 ms | 40.5 ms |
| 3000 节点挂载 LayoutCount | 3004 | 5 |
| 1200 节点挂载 LayoutCount | 1204 | 5 |
| 3000 节点重复投影中位耗时 | 13.6 ms | 1.9 ms |
| 相同投影的 DOM 变更（3000 节点） | 21000 | 0 |
| 只改变一个输出的 DOM 变更 | 21000 | 1 |
| 3000 装饰、30 次预览中位耗时 | 169.3 ms | 65.4 ms |
| 30 次预览重新建立的装饰边界 | 90000 | 0（只更新相关对象） |
| 30 次预览的全模型 reindex | 30 | 0 |
| 空装饰绘图层后备像素数 | 1296000 | 1 |
| 父页最小化通知后仿真冻结 | 否 | 是 |
| 最小化采样期间 Research RAF 回调 | 7 | 0 |

1200 节点旧源码耗时三次为 5371.3 / 1490.8 / 535.0 ms，首轮波动明显，因此不以该组耗时计算提速倍数。3000 节点旧/新三次分别为 3455.8 / 3615.1 / 3593.7 ms 与 164.6 / 163.2 / 162.1 ms。布局、DOM 变更和索引重建次数是主要回归约束；耗时只报告，不设跨机器硬门槛。

新增的深色英文 900px 窄窗、DPR 2、普通动态场景也通过：1200 节点挂载 65.5 ms、6 次布局，相同投影及重复英文错误展示零 DOM 变更。固定外壳测量带来少量布局，但不会随节点数增长为逐节点强制布局。

## 验证与复现

配置测试主机已有的 `RELATUM_PLAYWRIGHT`、`RELATUM_PYTHON`、`RELATUM_EDGE_PATH`，运行：

```powershell
$env:RELATUM_RESEARCH_ROUNDS = '3'
$env:RELATUM_RESEARCH_BASELINE_REF = 'd18b0f7'
$env:RELATUM_RESEARCH_REPORT = Join-Path $env:TEMP 'relatum-research-baseline.json'
node tests/research-performance-browser.js --baseline
$env:RELATUM_RESEARCH_REPORT = Join-Path $env:TEMP 'relatum-research-after.json'
node tests/research-performance-browser.js
```

脚本自行启停隔离服务，所有研究 GET/POST 使用合成文档替身，不接触真实研究数据。计数来自测试注入的 MutationObserver、模型/索引方法包裹、网格键统计及浏览器 CDP；生产代码不带计数探针、全局调试入口或性能常驻循环。超长连线用 ±1000 万坐标验证中段命中、重叠顺序、删除、移动、撤销和零超限网格分配。生命周期覆盖真实首页的研究 iframe、父页重复通知、显式暂停、离页后还原、重新激活及文档隐藏/返回。

已通过：

- 研究壳、画布、页面、计算、子电路、仿真、持久化、分叉、模型、直角几何、符号及教程共 12 个 Node 回归入口。
- `python -m unittest tests.test_research_store -v`：14 项，用临时 `RELATUM_DATA_ROOT`。
- `research-orthogonal-browser.js` 与其调用的原电路公开交互回归：模式/工具栏、真实拖线、移动、吸附、裁线、预设、取消、撤销、深浅、英文、窄窗、DPR 和低动态。
- `research-label-browser.js`：公式字号/缩放、标注边界与命中、文本框、候选交接、预设、失败回退及离页恢复；检查了浅色/深色 DPR 2 截图。
- `research-subcircuits-browser.js`：创建、固定修订、升级、复用及重载。
- `research-cpu-browser.js`：两版 CPU 程序、实例升级清空状态、25 Core 的 1006 叶节点 / 1356 导线，以及 Probe 顺序和非持久运行态。60 次单步中位 17.0 ms，P95 30.2 ms，无页面异常。
- `research-time-slicing-browser.js`：1000 同步 Clock 完整批次、协作让出、暂停/恢复、刷新与非持久运行态，无计算错误或 Long Task。

原生最小化路径通过浏览器派发桌面壳已有的真实事件协议验收；本轮没有重建 EXE，也没有新增真实 WinForms/WebView2 最小化或微软拼音候选窗的人工验收。1,000 时钟样本使用既有捕获方式，混合了模拟事件调度/RAF，不能把本次帧间隔直接与 9 月报告比较。表中的挂载优化不能外推为整个应用帧率、总内存或所有研究内容的相同提速比例。
