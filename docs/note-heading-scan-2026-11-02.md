# 笔记标题扫描的代码范围查找 · 2026-11-02

本轮复核近期的长文视口扫描、Callout 展示复用、标题滚动、统计及大纲更新路径后，仅修改共享标题扫描中的一处重复遍历。

## 问题与改动

`assets/note-live-editor.js` 的 `scanNoteHeadings()` 需要区分公式中的 `%%` / `<!--` 与真实注释，并排除行内代码中的伪公式。原实现对每个待检查公式调用 `inlineCode.some()`，从头遍历整篇笔记的行内代码范围。代码与此类公式同时增加时，这部分检查呈平方级增长。

行内代码范围由语法树按源码顺序生成，互不重叠。现在用二分查找定位第一个结束位置晚于公式起点的代码范围，再检查其起点是否早于公式终点，保留原有严格相交边界。单次查找为 O(log N)，不增加缓存、正文副本、观察器、任务或存储。

共享扫描器服务于可见大纲、阅读面的标题锚点及 `[TOC]`。标题规则、公式/代码/注释保护、分片调度、输入交接和持久化保持原样；没有调整主题、字体、正文几何或交互动效。

## 三轮浏览器对照

基线为 `5037fa0`，同一 Edge 进程、静态资产、合成 Markdown；旧/新页面顺序逐轮反转，每页先预热三次。计时不注入范围访问计数，另开页面单独测工作量。

混排段落含一处行内代码与两处带注释字符的行内公式，文首文末各一个标题。表内为三轮完整标题扫描耗时的中位数，单位 ms：

| 场景 | 字符数 | 基线 | 当前 |
| --- | ---: | ---: | ---: |
| 1000 段混排 | 54,906 | 16.8 | 9.9 |
| 4000 段混排 | 222,906 | 164.5 | 33.0 |
| 8000 段混排 | 446,906 | 618.7 | 56.5 |
| 8000 段普通代码/公式对照，无注释字符 | 422,906 | 59.8 | 55.8 |

8000 段混排的代码范围访问次数为 128,000,000 → 207,618；1000/4000/8000 段均满足每个公式最多约 log₂(N)+1 次查找。最大混排样本的完整扫描耗时减少约 91%。这是特定内容下扫描器的总计算时间，不是单次按键延迟、滚动帧率或整机 CPU 降幅；普通文字对照没有显示明显退步。
