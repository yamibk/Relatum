# 笔记语法与资源性能验收 · 2026-10-22

基线 `c22006b`。保留当前外观、目录、脚注、表格工具条、中文输入、撤销和工作区交接；没有修改 vendor、启动器管理方式、API、SQLite schema 或文件格式，也没有扩大缓存预算。

## 实现

- 标题扫描两处节点游标止于当前子树。原先每个段落都继续遍历到文末，形成平方级工作量；1000 段行内代码的 `inlineCode` 位置对象从 502500 个降到 1000 个。生成器仍可分批执行。
- Live 分别维护定义、未解析脚注使用点及目录标题。局部事务扫描受影响的段落、定义和保护边界，其他位置按 CM 变化映射；未闭合语法向后成倍扩展至中性边界。跨段公式配对及相关掩码结构、前言边界改变时保守重建。新增定义可激活前文未解析脚注，重复定义和首次引用编号保持原规则；普通选区变化不解析。
- 公式掩码由有序区间一次拼成，保留代码/注释前后两种公式保护解释。同次渲染复用掩码，阅读模式共用一次语法上下文，并保留内嵌画布占位前的跳转位置。没有跨笔记全文缓存或新后台循环。
- 浏览器回归捕获后台目录通知先登记移动目标、随后 `remap` 撞上唯一约束的既有竞态。确定性测试复现修复前的 `UNIQUE(book,key)` 异常；现在同一 SQLite 写事务保留原 entry 身份、转交入链并清理重复派生行。文件路径冲突和 Markdown 原子写入不变。

## 真实桌面资源

相同独立 EXE、WebView2 155，旧/新仅由测试响应替换两份 JS；每次新建库及 WebView 配置。完整模式运行 `Relatum.exe`，仅笔记运行免弹窗 `RelatumLauncher.exe`，各三轮交替。夹具包含目录、1000 段代码/引用/公式和脚注；首次稳定 10 秒后执行 30 次双笔记往返与 6 次阅读往返，每批强制 GC，最后采样 5 秒空闲 CPU。PID 去重汇总整个进程树，各轮均为 7 个进程。

交互阶段 CPU 时间减少约 57%–58%，范围是初次稳定采样至最终空闲采样前，包含批次 GC 和等待；由两次累计 CPU 差减去独立空闲窗口 CPU 得到，不是单次输入延迟。常驻私有内存只有小幅变化，GC 后堆基本相同，不能宣称显著降低常驻 RAM；主要减少的是交互计算和临时分配。空闲 CPU 单轮波动较大（约 1.4%–13.3%），不据此承诺稳定降幅。工作集包含共享页，不能等同独占物理 RAM。

三批循环的 GC 后堆满足稳定性门槛，所有样本空闲新增 RAF 为 0，正文及磁盘逐字不变。原始进程、堆、CPU 计数和推导方法：[desktop.json](validation/note-performance-2026-10-22/desktop.json)。
