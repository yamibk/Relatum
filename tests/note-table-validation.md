## Windows 桌面与 Microsoft 拼音

使用已有 Relatum 便携版的临时副本，覆盖本次六个前端资产，在独立数据根和 WebView2 用户目录运行。通过原生鼠标和键盘打开真实 Microsoft 拼音候选窗，没有用浏览器合成组合事件代替本节检查。桌面输入法实测后，仅补齐 Shift 扩展满行的结构选择规则，并增加反向范围和连续多列的浏览器用例。正式发行包未重新构建。

| 实际操作 | 观察及落盘结果 |
| --- | --- |
| 在文末表格下方单击后，用拼音确认“在”；连续再次输入 | 正文保存为“在在”，表格行列及原单元格保持不变。 |
| 正文与单元格之间切换后开始第一段拼音 | 候选窗位于当前单元格输入光标旁。独立测量镜像解决了原先输入框临时归零导致候选窗沿用前一输入宿主坐标的问题。 |
| 单元格候选未确认时保存 | 候选窗继续存在，磁盘只含已提交内容；预编辑 `h` 未提前落盘。 |
| 候选期间滚动，再用空格确认“和” | 原输入宿主保持挂载，确认值只写入原格，未产生额外行列。候选期间的滚动受到宿主保护；这不等同于承诺任意平台的候选窗都能随页面实时滚动。 |
| 候选期间点击另一格，再在新格确认“是” | 旧输入的最终值只提交原格一次，“是”只进入新格。实际源码分别为 `甲和h` 和 `是己`，未交换、重复或串格。 |
| 候选期间点击另一篇笔记 | 原值只写原笔记，`Other.md` 始终保持“另一篇隔离笔记，内容应保持不变。”；切回后保存值一致。 |
| 候选期间点击源码入口，再返回实时预览 | 等待原候选结束后切换，原格最终源码为 `是h己`，两张表格及正文保留，返回后正常渲染。 |
| 从表格内部留白拖过两行的全部列，Delete，再 Ctrl+Z | 连续整行选区可见；Delete 删除两行结构，一次撤销完整恢复三行及已有中文内容。 |

此机的 Microsoft 拼音在部分外点点击时，会在页面收到指针事件之前发出 `compositionend`，最终值可以是尚未选词的拉丁字母。实际顺序为 `compositionend → pointerdown → mousedown`，交接仍在 settling 阶段。以原生事件的最终值为准，在原目标提交一次；不得将候选阶段的值提前保存，也不得用“看起来像拼音”的过滤规则丢弃系统已经提交的合法拉丁文字。该事件顺序已有专门浏览器回归。

本节确认上述实际桌面场景。全部行列重排组合、图片/公式异步加载、主题和字号排列由浏览器回归覆盖，没有宣称在桌面逐一穷举；不同 Windows 输入法设置或 WebView2 版本仍应按同一隔离验收流程复测。
