# 笔记工作区收尾复查 · 2026-10-14

在本轮正文输入和大表格优化之后，复查了笔记切换、视图恢复、保存、搜索与侧栏交接、弹层、过渡及隐藏时的资源释放。本次产品改动限于 `assets/note-workspace.js` 的输入弹窗和 `assets/note-canvas/engine.js` 的重复 SVG 写入；没有新增依赖、偏好或数据格式，也没有操作真实用户笔记。

## 可复现问题与修复

缺失双链的创建确认框原来只添加覆盖层，没有转移焦点。正文光标仍在编辑器中，确认框打开后输入 `x`，真实 Markdown 会从 `正文\n\n[[Missing]]\n` 变为 `正文\n\n[[Missing]]\nx`。Escape 不关闭确认框；内嵌画布重命名的 Escape 原来也只在名称输入上有效。

两个弹窗现在共用一个临时会话：

- 挂载立即转移焦点，确认框先聚焦“取消”，重命名框先聚焦并选中名称。沿用已有入场过渡，等待动画不阻挡键盘隔离。
- Tab/Shift+Tab 在弹窗内循环；Escape 可从输入和按钮取消，关闭后在原正文和标签仍有效时恢复焦点。工作区的新建、关页、切页、搜索和保存快捷键不会作用于遮挡内容。
- 名称输入保留原生文本输入、复制/粘贴及撤销。输入法候选中的 Enter/Escape 和 229 键码不触发提交或取消。
- 同时只保留一个弹窗。替换结清旧 Promise，旧入场帧不重新聚焦；切换/替换正文、离开工作区和 pagehide 取消旧操作。提交核对正文和标签身份。
- 关闭移除临时文档监听并取消入场帧；没有新增闲置动画循环。后台轮询、保存和现有候选交接协议不变。

`node tests/note-modal-browser.js` 使用真实 Edge、生产函数和隔离 HTTP 服务验证以上行为。修复前明确失败于“被遮住的正文追加了 x”；修复后通过。

## 内嵌大画布挂载

1500 节点的画布验收曾在创建与离屏释放的 12 秒等待中超时。独立拆出渲染器后，确认节点测量会重写相同的 SVG `viewBox` 和轮廓 `d`，随后读取文本与节点尺寸；写入和读取交错重复触发布局，而不是数据或异步测试本身没有完成。

改动只检查属性实际值，跳过相同值的写入。尺寸、路径、自动撑高、节点文字和边的算法保持原样；新值仍照常更新，没有增加几何缓存或改变文件格式。

`node tests/note-canvas-layout-browser.js --performance` 使用同一 Edge、1000×800 视口、640×360 宿主、同一 CSS/字体、低动态和只读渲染器，旧/新交替各三轮。基线从 `fafc085` 读取原引擎，不回退工作区。计时只覆盖同步 `create()`，不含后续显示帧、文件 API、Markdown 投影或浏览器协议往返。

## 整体复查与验收

本次使用已有 Node、Playwright、Python 和 Edge 155.0.4283.45。所有真实保存、创建、改名、外部变化及重开都只使用临时数据根和新浏览器配置。

- `note-view-state-browser.js`：选择/滚动与模式往返、重开、自动外部同步、目录复用、重命名焦点、失败恢复及链接刷新交接。
- `note-ui-browser.js`：完整、仅笔记和关闭内嵌画布的三种外壳；搜索分页/失效、窗口化与焦点、选项复用、日期校验、深浅/窄窗/低动态及闲置零 RAF。
- `note-sidebar-browser.js`：侧栏展开反转、迟到脚本/标签、结果返回、原生候选和保存交接。
- `note-visibility-browser.js --mode=notes-no-canvas`：页面/原生最小化通知、图谱资源释放与镜头恢复、迟到目录/正文/链接/预读、大纲与统计暂停、搜索和候选保存。
- `note-canvas-browser.js`：真实画布改名与共享引用、Markdown 历史的撤销/重做、模式往返、独立画布保存冲突、功能裁剪及隐藏预热。
- `note-canvas-stability-browser.js`：51 档尺寸、12 种形状、小数尺寸、自动撑高和长文字、保存重开、静置零测量/重绘及功能外壳。
- `note-canvas-layout-browser.js --performance`：12 种形状和更新与旧版一致，500/1500 节点三轮对照及重复属性写入为零。
- `note-tab-motion-regression.js`、`note-workspace-contract.js` 和语法/差异检查：标签关闭补位、反转/清理及原工作区契约。

旧回归中几处等待与宽度断言已按当前源码校准：

1. 恢复的固定笔记可在目录首次注册完成前打开。原侧栏测试仅等待正文，曾拿到 `scanning`、一条固定笔记且没有文件夹的快照。现在先等待隔离库索引就绪并读取最终目录，再判断全部展开按钮。
2. 搜索 UI 测试测量显式提交的请求数量时，旧的首次目录快照及自动轮询会合法触发后台失效，干扰去重/分页断言。现在先提交最终目录快照，再暂停该测试的轮询和预读；失效仍由测试显式触发，真实后台同步另由视图和可见生命周期测试覆盖。250 项结果实际保留约 17–20 个可见行。
3. 画布改名和文件/文件夹移动会重写共享 Markdown 引用，后台要求索引完整。测试直接写入另一篇 Markdown，或在刚改名/保存后立即执行下一次移动，可能正确收到 `409/statistics_incomplete`。现在在测试中先完成这些准备写入并等待引用索引，且直接检查画布改名 Promise 的结果、重名失败的真实 `exists` 原因。产品原有完整性保护保留。
4. 右栏现有宽度已统一为 `--note-side-width: 320px`，画布旧测试仍使用 300px 上限。现在沿用 320px 契约并继续检查整个面板位于窄窗内，没有调整产品宽度或位置。
