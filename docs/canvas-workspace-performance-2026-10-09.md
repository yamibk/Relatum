# 画布工作区性能优化记录 · 2026-10-09

本轮覆盖文件管理、画布编辑器及树状、学习、速记、活跃、日历、复习、专注七页。重复绘制、全量历史复制和大列表 DOM 挂载已明显减少；3000 节点场景仍有渲染长帧，不能据此宣称所有大画布都能保持 60 fps。

## 实现与兼容边界

- 编辑器平移、悬停、箭头/拐点和已有拖动预览按显示帧合并最新位置。速度估计继续读取原始事件，手写保留合并事件中的全部采样。释放先提交最终坐标，取消、失焦、隐藏和离页清理排队任务。
- 选区只更新旧、新集合的差集，签名不变时跳过面板刷新和通知；绑定文字框按目标建立索引。视口边界复用已有尺寸缓存，避免每个平移或缩放事件强制测量。
- `canvas-changes.js` 用一个隔离的当前状态与最多 49 条实体事务保存约 50 步历史。普通事务存受影响实体的前后状态，仅在顺序变化时记录顺序；未改墨迹共享历史记录，不复制笔画点。撤销重做沿用对象/附件身份与计时语义。整体替换、导入和无范围的兼容调用继续走完整快照。通知集合独立于事务，防止合并通知污染历史。
- 手写笔画边界与 SVG 路径按身份缓存，橡皮只细查边界候选并替换命中片段。速记拖动及惯性复用尺寸和相邻连线索引；编辑尺寸变化、叠摞动画和收尾仍校准真实几何。离页、Esc、失去捕获和失焦取消未完成手势。
- 文件和复习列表超过 200 项时使用共用的 `windowed-list.js`，挂载可见行及上下各约一屏。实际行高由 ResizeObserver 校准并保持滚动锚点。改名/焦点行独立保留，旧 WebView2 不重新插入输入宿主。筛选、排序、全选及批量操作使用完整模型。
- 每日任务按组、父组和任务建立索引，完成度汇总缓存只失效相关祖先。树状页和学习目标树在一次动画中复用工作集，只写变化节点及其相邻线；独立 CSS `translate` 保留入场/拖动 `transform`，能力不足时回退到 `left/top`。
- 星图预布局按约 4 ms 分片，完成后开始原有入场时钟。隐藏、离页、换数据、销毁和低动态切换作废旧任务；标签和装饰只在值变化时写入。单个物理步不能进一步拆分，因此片长可超出预算。
- 画布首页保留沉浸背景构图，常驻背景静态化，顶栏使用高不透明度渐隐表面并移除背景模糊；游标/搜索光晕有限播放，减少常驻 `will-change`。翻页节奏及低动态降级保留。

没有新增 HTTP API、数据格式、偏好键或应用依赖；后端路径授权、原子保存、附件生命周期和完整导出边界保持不变。日历等未发现需要改造的页面保留实现，纳入切换及闲置回归。

## 测量方法

基线为 `634b96a1cffb86b1d99e285bed04a56b0b8b3eac`。浏览器使用本机 Edge `154.0.4258.62`；常规画布基准为 1440×900、DPR 1，大列表探针为 1280×800，并覆盖 DPR 2、深浅主题、680×650 窄窗和低动态。全部功能夹具、保存及桌面验收写入一次性隔离数据根，列表大数据使用 API 替身，不读取用户列表。

下表的计数来自真实页面内探针。事件突发把多个输入放在同一事件循环中，测量合并效果；其同步 JS 时间不含下一帧绘制，不能换算成持续拖动帧率。历史耗时为五次普通节点提交的中位数，包含 3000 节点和指定数量的手写点。完整样本和口径见 [测量数据](canvas-workspace-performance-2026-10-09.samples.json)。

| 场景 | 基线 | 优化后 |
| --- | ---: | ---: |
| 3000 节点，120 次平移事件/同一帧 | 120 次绘制 | 同步绘制 0 次，下一帧 1 次 |
| 上述平移突发同步 JS | 34.3 ms | 0.5 ms，视口读取 1 次 |
| 同一选区重复 12 次：`selected` 切换调用 | 71640 次 | 1 次；重复选区通知 0 次 |
| 普通节点提交，5 万手写点 | 9.4 ms | 1.9 ms |
| 普通节点提交，20 万手写点 | 26.9 ms | 1.5 ms |
| 普通节点提交，50 万手写点 | 74.9 ms | 2.4 ms |
| 上述提交及撤销重做读取未修改的墨迹点 | 基线复制全部点 | 优化后探针读取 0 次 |
| 96 张便签，60 次拖动事件：便签几何读取 | 5760 次 | 1 次；500 张夹具同样为 1 次 |
| 2000 张复习卡筛选后挂载的行 | 2000 行，约 20000 个行内元素 | 5 行；一万张夹具为 5 行 |
| 2000 / 10000 文件的挂载行 | 原实现全量挂载 | 两种规模均为 16 行 |
| 600 个叶任务的星图同步挂载 | 129.0 ms | 14.2 ms，后续布局分片 |
| 首页沉浸背景 / 顶栏背景采样 | 无限动画 / `blur(22px)` | 静态 / 无模糊 |

“切换调用”不是属性实际变化次数；列表行数是指定视口的一次采样，滚动、焦点保留、实际行高变化时会变化。窗口化只限制 DOM，完整数据仍在内存中：一万项场景页面总 DOM 为 2695 个元素，JS 堆采样约 16.8 MB；2000 项约 10.7 MB，不能解释成内存与数据规模无关。便签突发 JS 时间在复测间存在波动，本轮以几何读取计数和实际连线误差作为稳定验收条件。

## 多轮实际操作与剩余瓶颈

1200/3000 节点各运行五轮冷启动及同页热启动，检查局部缩放、25% 总览、平移、拖动、收尾和撤销；测试均通过。1200 节点局部缩放帧间隔 P95 约 16.8–17 ms；3000 节点部分缩放/全景移动仍有 50–83 ms 的长帧。冷启动受文件缓存和 CPU 状态影响，本轮不把启动数字作优化收益。

另在同机交替装载旧、新画布核心各三轮，3000 节点缩放和平移 P95 均约 66 ms，确认旧版也存在这项瓶颈。三轮撤销同步 JS 中位数由 20.6 ms 降至 13.2 ms，经过帧/布局的收尾中位数由 73.2 ms 降至 42.6 ms。该操作区间样式重新计算次数中位数由 220 降至 195；总任务时间及布局耗时仍有波动，不作总体 CPU 或渲染提速承诺。

96 便签的真实相机操作另做三轮：143–145 个采样帧只读取便签几何 22–23 次，没有新增/删除静态连线 SVG；连线端点误差最大约 0.058 px。各页闲置观察没有留下速记排队帧或便签几何读取。

真实桌面使用项目已有 pywebview 环境和 WebView2 `154.0.4258.62`，1280×800、Windows 缩放 150%（DPR 1.5）。通过原生窗口输入复查 3000 节点拖动、撤销、重做和滚轮缩放：节点从 `(260,0)` 拖至 `(366,42)`，撤销恢复，重做回到相同坐标，连线及小地图随动。该次桌面撤销/重做同步 JS 为 9.9/9.5 ms，收尾为 33.9/24.4 ms；拖动收尾仍出现 342.9 ms 的延迟。这是功能与呈现验收，不是持续鼠标采样的硬件帧率测量。

尚存的主要成本是大量节点 DOM、文字样式及 Canvas 栅格化。本轮没有引入节点回收或替换绘制后端，避免扩大编辑、焦点、附件和命中边界。高刷新率覆盖使用虚拟 60/120/144/240 Hz 调度，不能代表每种物理显示器；中文输入覆盖合成 composition 和改名焦点保留，不能替代所有原生输入法候选窗组合。

## 回归结果与复现

- Python 172 个测试通过，涵盖树、学习目标、进度、复习、每日任务、任务簿/归档、功能选择、导入、最近分组、便签、日历及前台活动。测试进程在导入 `app` 前设置新的 `RELATUM_DATA_ROOT`；部分旧测试只替换若干路径，不应直接在真实数据根运行。
- JS 回归、契约与语法检查通过，包括实体历史、手写、树动画/位置回退、星图分片、每日任务汇总、文件搜索/最近同步、书脊、计时器、镜头册、任务簿、矩阵、导入、普通节点尺寸及尺子。
- 浏览器通过：多种节点撤销/重做、实体身份、50 步边界、墨迹局部擦除和压力/倾斜点、整体导入/回滚、完整 PNG/SVG 导出、图片/Markdown/PDF 按需生命周期、导图/折叠、任务簿、别名、拐点、双屏、快速反向切页、取消/失焦/离页、释放最终坐标及保存失败后重试。
- 大列表通过：2000/10000 项滚动到底、完整筛选结果全选、改名输入焦点和中文候选保留、旧 WebView2 排列回退、实际行高变化后维持滚动锚点、窄窗及主题/低动态。96/500 便签验证局部测量、连线、取消和排队任务清理。
- 树和学习目标树用 1200 节点密集夹具验证四种虚拟刷新率；每日任务用 100 个嵌套组和 2000 个任务验证索引及祖先缓存失效。星图验证离页/返回、数据替换、销毁和低动态途中切换不会执行过期布局。

无需给项目安装 npm 依赖。复用测试机已有 Python、Playwright 和 Edge；设置 `RELATUM_PLAYWRIGHT`、`RELATUM_EDGE_PATH`，自建隔离服务时还需设置 `RELATUM_DATA_ROOT`：

```powershell
python -B tests/generate-performance-fixtures.py <新建的隔离目录>
# 在单独终端设置 RELATUM_DATA_ROOT 为该目录后启动 app.py --no-browser。
node tests/canvas-workspace-performance.js <隔离服务URL> <隔离目录> <报告.json>
node tests/canvas-browser-performance.js <隔离服务URL> <隔离目录> <报告.json> regression
node tests/canvas-browser-performance.js <隔离服务URL> <隔离目录> <报告.json> benchmark
node tests/canvas-changes-regression.js
node tests/canvas-workspace-layout-regression.js
node tests/graph-presolve-regression.js
```

速记和手写浏览器脚本自己管理测试服务，另设置 `RELATUM_PYTHON` 为可用 Python 路径：

```powershell

node tests/canvas-ink-regression.js --browser --report <报告.json>
```

以上报告只能写入隔离目录。结束时关闭测试服务及测试窗口；不能把一次性夹具、用户数据或测试主机路径提交进产品资产。
