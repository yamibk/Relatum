# 计划复习：每日补练与安全评分

## 用户规则

“推送”指进入本地计划复习队列，没有通知或后台提醒。只有当前范围内、处于复习中且已到期的卡片进入队列。自由复习继续随机浏览，不写评分、完成或调度记录。

| 评分场景 | 今日状态 | 等级及下次日期 |
| --- | --- | --- |
| 今天首次记得，且无未完成补练 | 完成 | 升一级，沿用 1、3、7、16、35 天间隔 |
| 模糊 | 开始或重置补练，连续次数为 0 | 从当天初始等级降一级，最低 0；今天仍到期 |
| 不会 | 开始或重置补练，连续次数为 0 | 回到 0 级；今天仍到期 |
| 补练中记得一次 | 连续记得 1/2 | 不升级，今天仍到期 |
| 补练中连续记得两次 | 完成 | 不升级，明天巩固 |

同一天重复模糊不连续降级；当天出现过不会，后续模糊不恢复等级。补练再次失误重新计数。当天关闭、刷新或换页保留进度；未完成补练跨天接续，但连续次数清零。完成后的下一次正常首答记得仍按间隔表升级。

每轮 10/20/50 指不同卡片数量。未过关卡放回剩余队列 3 张之后，数量不足则提前，单卡在点击“继续”后重新出题并收起答案。补练不占额外名额，全部过关并确认最后一张答案后才显示本轮完成；“再来一张”先核对答案，继续时只轮换当前卡，不评分。刷新可以重建当前批次，已持久化的补练和完成状态不丢失。

顶部“今日完成”按本地日期、稳定卡片 ID 去重，删除卡片不抹去既有完成记录；该数为全库今日完成数，沿用原今日作答统计的全库范围。“待复习”和范围选项按当前范围统计，仅过关时因日期推进而减少；暂停、归档等管理操作也会影响可用卡片数。本轮进度显示完成数，补练卡显示连续记得 0/2 或 1/2。

## 数据与升级

`app.py` 管理 `data/review.db`，schema v5 在原 v4 上增加：

- `review_daily_progress`：主键 `(card_id, review_day)`；保存当天初始等级、待补练、连续记得、当天是否不会、完成及更新时间。卡片身份不设级联外键，历史完成可在删卡后保留。读取时批量查询不晚于今天的最近一条状态，跨天只继承未完成补练，不沿用旧连续次数。
- `review_mark_requests`：请求 ID、规范化评分摘要、完整结果 JSON 和创建时间。与卡片、评分事件及每日进度一同提交或回滚。

v3/v4 升级保留原卡片、等级、到期日、设置、导入收据和所有评分事件。只对升级当日本地时间范围内、仍有稳定卡片 ID 的旧事件接续：当前日期已排到未来的卡按 ID 去重为完成；仍到期的卡以补练 0/2 接续。不会把未来卡拉回今天，也不凭问题文本猜测已删除旧卡的身份。新建及导入卡不预写评分或每日完成。

迁移使用 SQLite 即时事务及版本复核；正常 v5 连接不重复执行建表或默认设置写入。卡池先在 SQL 中过滤 active、范围和到期条件，再排序和限制批次。卡片、标签、每日状态、设置及统计在同一读取事务快照中取得；标签与每日状态按最多 400 个卡片 ID 分块，无逐卡历史查询。

## 保持原路径的接口扩展

卡池及卡片库中的每张卡新增：

```json
{"dailyReview":{"day":"2026-10-16","needsRelearning":true,"streak":1,"target":2,"completed":false}}
```

`POST /api/review-mark` 的前端请求：

```json
{"cardId":"稳定卡片 ID","rating":"remembered","requestId":"本次唯一 ID","expectedReviewCount":7,"reviewDay":"2026-10-16"}
```

`rating` 保留 `remembered/vague/forgot`。服务端保持旧调用兼容；新前端始终提供请求 ID、评分版本和日期。Python `mark_review_card(id,rating)` 仍返回单张卡，新事务入口为 `review_mark_payload(payload)`。

卡池和评分响应新增 `completedToday`、`scopeKey`，保留 `reviewedToday`（作答次数，使用原事件时间范围索引）；评分还返回卡片、当前范围 `count/dueCount` 和各范围 `scopes`，前端不自行减数。评分结果带 `requestId/generatedAt`，相同请求重试返回原响应并附 `idempotent:true`。原响应统计是原事务快照，前端收到重试结果后另外刷新当前统计。

收据查询优先于日期、卡片存在性、状态和版本校验，因此提交成功后即使跨天或删卡仍可安全确认原请求。不同内容复用 ID 返回 `409/request-conflict`；日期冲突为 `day-changed`，版本冲突为 `stale-card`，其他 409 为 `card-inactive/card-not-due/already-completed`；卡片缺失 404，字段格式无效 400，SQLite 写入失败 500。失败不留下半条评分、进度或收据。原功能裁剪仍在数据库访问之前拒绝禁用的复习接口。

## 页面交接与说明

`assets/review.js` 将出题、保存、核对答案分开：点击评分立即展开原卡答案，保存成功更新一次统计与补练队列，但不自动换卡。“下一张/再来一张”同样先核对，继续后才执行无评分换卡。已展开的答案不重新渲染，空答案显示“未填写答案”；草稿保留到实际换卡，最后一张也先留给用户核对。

核对时评分按钮稳定变灰，用 `aria-disabled` 锁定并保持焦点，不使用透明度闪烁。右侧原按钮改为“继续”，旁边显示“按任意键继续”；实际接受 1、2、3、N、D、Space 和 Enter（不区分字母大小写），悬停与无障碍说明列出按键。继续只推进一次，不把当前事件再当作下一卡评分；按键释放前、自动重复、双击第二次点击不推进。输入框、输入法候选、弹窗、下拉及 Ctrl/Cmd、Alt 组合键保留各自用途。没有新增持久化设置、依赖、接口或数据库字段。

保存中或结果不确定时不能继续，也不排队一次继续。无法确认的请求保留原始 payload 和当前答案/草稿，显示“重试保存”；确认成功后才能继续，收据重放不会重复更新队列或评分。409/404 刷新权威卡片，仍是同卡时恢复草稿。

异步响应核对会话身份、模式、范围与本地日期；切换模式、范围、离页或午夜前的请求不能推进新会话。已进入核对阶段后临时离页、隐藏或最小化不推进，返回同次会话保留等待；切换模式/范围、刷新或跨天作废旧等待，已保存评分不撤销、不重做。保存时转入卡片库，结果确认后单独刷新权威统计，不推进批次。跨天后的下一次评分/跳过/继续先刷新状态。正常补练只更新变化的元数据与统计，补练首次成功不播放完成数 +1；自由浏览计数与换卡提示只在真正继续换卡时更新。

`assets/index.html`、`assets/i18n.js` 和限定的 `assets/styles.css` 更新两种语言的帮助。卡片库“复习规则”默认仅展示出题条件、评分及完成；“更多说明”默认收起，含间隔/顺序、管理与导入。沿用轻量过渡，正文可滚动、底部按钮可见；英文评分名称预留宽度，窄窗避开左侧导航，深色面板不透底。快速说明同步保留原快捷键。
