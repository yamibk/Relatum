# 笔记表格行内 Markdown 编辑提示

表格中的当前编辑格与正文共用加粗、斜体、删除线、高亮和行内代码的文字装饰及标记显隐规则。光标或选区涉及格式时显示淡色标记，移到普通文字后隐藏标记；`POWER_SOURCES`、转义、未闭合记号及代码、公式里的符号保留原有语法边界。

## 实现与边界

- `note-table-editor.js` 只为当前格创建一个稳定的轻量 CodeMirror；其他格继续使用现有静态渲染。子编辑器不装配历史、标题、列表、图片、公式或其他块组件，退出格或销毁表格时释放。
- `note-live-editor.js` 共用行内文字和高亮装饰函数。格内使用已有 Lezer 的公开 `parseInline`，普通文字直接跳过，光标移动复用不可变格内文档的解析结果；弱引用缓存不进入持久化。
- 普通输入沿用原 `cellUpdateEffect` 和单行序列化，父编辑器仍是已提交 Markdown、历史及保存的唯一来源。候选期间只映射已有装饰，预编辑文字留在子编辑器，结束并等到两帧及 CodeMirror composition 退出后再统一交接。
- 点击与选字读取真实字形矩形及 CodeMirror 坐标，不再创建纯文本测量镜像。高度由自然排版决定，编辑宿主不归零、不在候选期间重挂；格式快捷键、导航、剪贴板、跨格选区、列对齐和重排沿用现有控制器。
- 表格内的 `img.cm-widgetBuffer` 必须保持行内布局，覆盖表格图片通用的块布局、边距和装饰，否则隐藏语法标记会产生多余空行。
- 不新增依赖、用户偏好、后端接口或数据格式；图片、链接、公式的既有展示链路不改变。

## 验证

全部使用合成正文或一次性笔记库，浏览器采用本机 Edge 与已有 Playwright。截图、报告及保存数据只输出到系统临时目录。

性能入口为 `RELATUM_NOTE_INPUT_BASELINE=HEAD node tests/note-input-browser.js --performance-only --no-regression`，实现未提交时对照原生格输入版本的脚本与 CSS，4000/8000 格各交替三轮。检查宿主及其他格 DOM 复用、零全表解析/序列化/遍历、零其他格内容变更和局部数据行替换；输入耗时按相同宿主允许的绝对/相对预算检查。历史提交后复验应将基线变量指定为本次修改前的提交。

本机对照 `0045db0` 的三轮结果：4000/8000 格当前输入中位数的三轮中位均约 1.1ms，原版均约 1.0ms；当前 P95 的三轮中位分别约 1.6/1.5ms，原版约 1.3/1.4ms，通过既有同机绝对/相对容差。两种规模均保持零全表解析、序列化、遍历及其他格内容变更，输入宿主与其他格 DOM 保留。这些耗时只代表本机本次测试。

鼠标容错测试改为按真实行间距限制上下取点距离。原先固定偏移 3px，在窄窗 135% 字号下会更接近相邻行；使用旧版脚本与 CSS 可复现相同落点，不能据此将相邻行位置误判为新编辑层错误。

候选结束后立即点击正文的同步事件用例明确传入 `detail: 1`，表示一次单击；省略时值为 0，连续复用同一编辑器会让 CodeMirror 按多击状态选择整个单词/行，随后的键入会正确替换该选区，不能将这种测试事件当作普通单击。

静态回归覆盖 Markdown、表格、实时编辑器、Typora 语法、笔记工作区、代码、Callout 选区及语法索引。用户明确要求跳过微软拼音桌面验证，本次未进行该项验证，也未重新打包 EXE；浏览器 composition 检查不等同于真实微软拼音候选窗验收。
