## 全库名称搜索排序

`start.js` 原先在每次标题比较时调用带 `numeric:true / sensitivity:'base'` 选项的 `localeCompare`，反复准备自然排序规则。未打开画布较多、或打开时间相同时，全库搜索每次输入都会承担这项排序开销。

现在第一次进入全库排序时创建一个比较器，后续复用。区域仍取原来的浏览器默认值，保留打开时间优先、未打开置后、数字排序、大小写/重音处理及 id/path 平局规则；不缓存排序结果或改写元数据，搜索仍逐次使用最新标题与时间。

Edge `155.0.4283.45`，两种区域各五轮旧/新交替测试，中位数如下。夹具含多数未打开条目、相同打开时间、无效日期，以及中文、数字、重音、全角和 Unicode 名称；只计排序，不含 DOM 更新或完整输入响应时间。

## 归档读取与响应构建

`app.py` 的归档汇总原先对同一学习归档目录分两遍处理学习/任务簿和速记，分别调用 `is_dir/is_file`；活跃响应随后为 marker 总数再次遍历全部目录。目录数增长后，重复文件状态查询成为可见开销。

现在每次请求使用 `os.scandir` 收集学习、任务簿、速记及画布的已知 marker。活跃响应的记录和归档 marker 数量复用这次清单；日历独立请求重新枚举。清单只短暂保存路径，没有持久化索引、正文缓存或跨请求目录缓存。

保留原有文件名大小写与符号链接行为；非目录/非文件 marker 跳过，坏 JSON 不产生记录但仍按原逻辑计入 marker 数。保持同时间记录的类别顺序。子目录无法枚举时仍尝试原来的已知文件名，文件在枚举后消失按原读取异常规则跳过。正文读取、路径授权及原子写入均不更改。

Windows 本机一次性夹具：300 个学习归档目录、每目录 10 条记录，共 3000 条。五轮旧/新交替的中位数：

| 后端操作 | 原构建 | 当前构建 | 减少 |
| --- | ---: | ---: | ---: |
| 足迹记录汇总 | 342.1ms | 274.9ms | 约 20% |
| 月历响应构建 | 363.1ms | 285.2ms | 约 21% |
| 活跃页响应构建 | 480.6ms | 302.6ms | 约 37% |

这组对照隔离其他数据提供者，复用同一批真实归档文件并逐项比较响应；不包括 HTTP 传输/序列化、真实使用统计数据库、日记正文或页面渲染时间，不能解释为整页固定提速百分比。正文仍按请求读取，外部新增、替换、删除、根目录变化均无需等待缓存失效。基线为 `7c6bd6486349b2defd051409017a455490822120`。
